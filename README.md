## 🏁 Getting Started

```bash
pnpm install

```

| `pnpm lint`   | ESLint 검사               |

<a id="directory-structure"></a>

## 📂 Directory Structure

```
src/
├── app/
│   ├── App.tsx
│   └── main.tsx
│
├── routes/                       # 라우터 설정
│
├── pages/                        # 라우트 진입점 (도메인 컴포넌트 조합만)
│   ├── material-detail/
│   │   └── material-detail.tsx
│   └── cart/
│       └── cart.tsx
│
├── domains/
│   ├── material/                 # 자료 상세
│   │   ├── api/
│   │   ├── components/
│   │   ├── hooks/
│   │   ├── utils/
│   │   └── types/
│   │
│   └── cart/                     # 장바구니 + 폴더
│       ├── api/
│       ├── components/
│       ├── hooks/
│       ├── utils/
│       ├── constants/
│       └── types/
│
└── shared/                       # 공통 리소스
    ├── api/
    ├── assets/
    ├── constants/
    ├── hooks/
    ├── styles/
    ├── types/
    ├── ui/
    │   └── layout/               # 헤더, 푸터, 전체 레이아웃
    └── utils/
```

- 의존 방향은 **`pages → domains → shared`** 입니다. 도메인끼리는 서로 import하지 않고, `pages`에서 조합합니다.
- `shared`에는 특정 도메인에 묶이지 않는 코드만 둡니다.
- 스타일 파일(`*.css.ts`)은 컴포넌트 바로 옆에 둡니다.

<a id="convention"></a>

## 🗂️ Convention

### 🔁 Git Flow

| 브랜치                        | 용도                                            |
| ----------------------------- | ----------------------------------------------- |
| `main`                        | 배포 브랜치 (직접 push 금지)                    |
| `develop`                     | 개발 통합 브랜치                                |
| `{타입}/{기능명}/#{이슈번호}` | 작업 브랜치 (예: `feat/cart-compare-table/#12`) |

<details>
<summary><b>🚀 개발 프로세스</b></summary>

<br />

1. 작업 전 이슈를 발행하고, 이슈의 **Development → Create a branch**로 브랜치를 연결합니다.
2. 기능 단위로 작게 커밋합니다.
3. `develop`으로 PR을 올리고, 이슈 번호를 연결합니다.
4. CI(lint · format · build)를 통과하고 **2명 이상 Approve**를 받습니다.
5. PR 작성자가 직접 **Squash and Merge**하고, 작업 브랜치는 삭제합니다.

</details>

<details>
<summary><b>📝 커밋 컨벤션</b></summary>

  <br />

**`타입: 작업 내용`** (예: `feat: 장바구니 폴더 탭 구현`)

- 기능 단위로 작게, 무엇을 했는지 구체적으로 작성합니다.
- `feat: @@ 페이지 완성`, `fix: 리뷰 반영`처럼 내용을 알 수 없는 메시지는 쓰지 않습니다.
- 메시지에 특수기호는 사용하지 않습니다.

| 타입                | 의미                                    |
| ------------------- | --------------------------------------- |
| `init`              | 초기 세팅                               |
| `feat`              | 새로운 기능 추가                        |
| `fix`               | 버그 수정                               |
| `hotfix`            | 치명적인 버그 긴급 수정                 |
| `refactor`          | 코드 리팩토링                           |
| `style`             | 스타일 코드 변경                        |
| `type`              | 타입 수정                               |
| `asset`             | svg · 이미지 등 디자인 파일 추가        |
| `docs`              | 문서 수정                               |
| `chore`             | 패키지 매니저 · .gitignore 등 기타 수정 |
| `build` · `ci`      | 빌드 · 의존성 · CI 설정 변경            |
| `perf` · `test`     | 성능 개선 · 테스트 코드                 |
| `rename` · `remove` | 파일 · 폴더 이름 변경 및 이동 · 삭제    |
| `revert`            | 이전 커밋 되돌리기                      |
| `deploy`            | 배포 관련 작업                          |

</details>

<details>
<summary><b>🔀 이슈 · PR · 코드리뷰</b></summary>

<br />

- 이슈 · PR 제목은 **`[Type] 작업 내용`** 으로, 타입의 첫 글자만 대문자로 씁니다. 제목의 `[Type]`으로 라벨이 자동 지정됩니다.
  - `[Init] 프로젝트 초기 세팅` · `[Feat] 버튼 컴포넌트 구현` · `[Fix] 색상 수정`
  - 라벨이 자동 지정되는 타입: `Init` · `Feat` · `Fix` · `Hotfix` · `Refactor` · `Style` · `Chore` · `Docs` · `Asset` · `Deploy`
- 하나의 이슈 · PR에는 하나의 작업만 담습니다.
- 스쿼시 커밋 메시지는 PR 제목을 그대로 사용합니다. (예: `[Feat] 로그인 기능 추가 (#12)`)
- 리뷰 없는 신뢰 머지는 하지 않습니다. 코드리뷰는 정성껏, 말투는 둥글게 남깁니다.

</details>

### 📄 Code Convention

<details>
<summary><b>📂 폴더 · 파일명</b></summary>

  <br />

- 폴더명과 파일명은 **kebab-case**로, 소문자로 시작합니다. (`cart-list-row.tsx`)
- 여러 항목을 모으는 폴더는 복수형을 사용합니다. (`components`, `hooks`, `utils`)

</details>

<details>
<summary><b>⚛️ 컴포넌트</b></summary>

  <br />

- 리액트 컴포넌트만 **PascalCase**를 사용하고, `default export`합니다.
- 의미 없는 `div` 대신 시맨틱 태그를 사용합니다.
- 최상단 래퍼가 필요 없으면 Fragment(`<>...</>`)를 사용합니다.
- children이 없으면 self-closing으로 씁니다. (`<Component />`)

</details>

<details>
<summary><b>🧩 타입</b></summary>

  <br />

- 타입 이름은 **PascalCase**를 사용합니다.
- `type`보다 `interface`를 우선 사용하고, 유니언 · 튜플 · 리터럴 타입이 필요할 때만 `type`을 씁니다.
- Props 타입은 `컴포넌트명 + Props`로 짓습니다. (`HeaderProps`)
- 그 외 타입에는 `Types` 접미사를 붙입니다.

</details>

<details>
<summary><b>💡 변수 · 함수</b></summary>

  <br />

- 함수는 **화살표 함수**로, 이름은 **동사 + 명사**로 짓습니다.

| 접두어          | 의미                     |
| --------------- | ------------------------ |
| `get`           | 값을 가져와 반환         |
| `create`        | 새로운 값 생성           |
| `check`         | 로직 확인                |
| `convert`       | 형태 변환                |
| `add` · `minus` | 수치 연산                |
| `filter`        | 배열 필터링 결과 반환    |
| `is`            | boolean 반환 (`isEmail`) |

- 이벤트 핸들러에만 `handle`을 붙이고, 동작까지 드러냅니다. (`handleResetClick`)
- 배열 복사는 스프레드 연산자, 반복은 `for`보다 `map` · `forEach`, 객체 · Props는 구조 분해 할당을 사용합니다.
- `key`에 랜덤 값은 쓰지 않습니다. 동적 리스트는 고유 `id`를 쓰고, `index`는 순서 · 개수가 바뀌지 않는 정적 리스트에서만 씁니다.

</details>

<details>
<summary><b>🎨 스타일 (vanilla-extract)</b></summary>

  <br />

- 스타일 이름은 **camelCase**로, 의미가 드러나게 짓습니다. (`textContainer`)
- 요소를 감싸는 wrapper는 `container`로 통일합니다.
- CSS 속성은 바깥에서 안쪽 순서로 작성합니다.
  - `display` → `position` → `width` · `height` → `padding` · `margin` → `border` · `background` → `color` · `font` → `text-align`

</details>
